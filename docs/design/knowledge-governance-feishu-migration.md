# 识渊知识库升级改造与部门飞书迁移方案

立项评审稿 · 2026 年 11 月 25 日

## 一、立项目标与交付范围

现有飞书知识库由整个部门共用，产品、业务、客户、售前、售后和周报混在同一棵 Wiki 树中。部分父节点既有自己的正文，又承担目录导航，子节点也可能属于不同业务或只有部分成员可见。直接沿用飞书目录同步，会把原来的分类和版本问题带到识渊，也无法单凭源目录判断目标读者。

本次升级交付五个模块，使部门可以分库负责、按库授权、审核发布，并按核定清单迁移飞书资料。验收时，业务人员应能找到当前有效资料，库负责人应能管理自己负责的库，部门应能查清每个已盘点飞书节点的去向。

| 编号 | 功能模块 | 目前的问题 | 一期交付 | 满足的业务要求 |
| --- | --- | --- | --- | --- |
| M1 | 知识库管理与目录 | 可以建库、建文件夹，但缺少统一的业务归属、管理人和分库口径 | 改造知识库管理页面，支持库类型、业务归属、主备负责人、可见范围、复核日期、状态及交接 | 管理人员能查每个库谁负责、服务谁、处于什么状态 |
| M2 | 单库授权和共享 | 工作空间角色覆盖面较大，同一空间 Viewer 通常可读取其自有库，空间 Admin 可管理多库 | 新增受管库的用户级角色和名单管理，区分部门可读与指定成员可读，统一校验直接访问和共享入口 | 产品、售前、售后可各自维护，指定客户资料限名单访问 |
| M3 | 资料审核与生命周期 | 手工文档有草稿与发布状态，上传和同步文件缺少统一业务发布流程 | 增加审核队列、草稿版本、正式发布、到期复核和下架，正式入口按生效版本提供访问 | 员工检索和问答使用已审核、仍有效的资料 |
| M4 | 飞书盘点和按清单迁移 | 连接器按根节点递归，复用源树，数据源绑定一个目标库 | 复用连接器，增加节点盘点、逐条映射、批次预检、试迁、对账及重试，支持同一源子树分发至多个目标库 | 能拆解历史混合目录，保留原链接并查清每项处理结果 |
| M5 | 业务审计与迁移验收 | 有库活动和同步日志，业务审批和迁移结果需要统一追踪 | 补齐负责人交接、库授权、发布、下架和迁移审批事件，提供按库、文档和批次查询及对账导出 | 回答谁批准、谁执行、何时生效、哪批需要回退 |

首批聚焦一个部门。客户受限资料、周报原件及无法确认权限的内容，在确认授权和保留口径后再决定进入哪一批。逐文档复制飞书权限、组织目录自动同步、双向同步列为后续需求。确有逐文档权限保留要求的内容，在本期按受众拆库或保留在飞书。

## 二、五个模块分别怎么改

### M1 知识库管理与目录

- **改造入口。** 扩展知识库列表和编辑设置。列表能按业务分类、归属部门、业务负责人、状态筛选。详情展示库 ID、使用说明、主责与备份负责人、可见模式、最近复核和下次复核日期。
- **管理动作。** 部门指定经办人建库，按第三节选定库类型和使用范围。支持正常运行、归档两种正式状态，并记录负责人交接。主责离岗时，由有权的经办人接续，主备负责人字段与操作权限分别校验。
- **结果验收。** 用产品库和售后库演示管理列表、筛选和负责人交接。交接后责任标识与角色授予均有记录，管理员可以按库 ID 查到何时交接、由谁接手。

### M2 单库授权和共享

- **权限规则。** 受管库提供「空间成员可读」和「指定成员可读」两种模式。指定成员模式下，用户拥有适用的单库授权或已批准的共享路径时才能访问内容。工作空间角色用于管理空间和核验成员身份，空间 Owner 或 Admin 管理受管库内容也需符合该库授权。新增库角色仅在明确授予的库和操作上生效。读权限覆盖标题、摘要、原文和附件等实际可获取内容。
- **管理动作。** 库设置增加成员与权限和访问到期日。空间 Owner 指定库管理员，库管理员可维护本库目录、提交和执行经批准的授权、维护日常资料，库编辑可提交资料及版本，审核人审批发布，读者可阅读和问答。同一人可按业务分工兼任角色，实际授权记录脱离负责人字段单独保存。扩大可见范围和跨空间共享由业务负责人批准，再由有权经办人执行。受限库默认关闭跨空间共享，确需开放时核对整体受众再单独批准。
- **统一校验。** 后端以当前库权限校验列表、文档详情、检索、问答、Wiki、图谱、引用、原件与附件。已有组织共享、共享智能体、API Key、MCP 和 IM 等启用入口也要复用权限边界。平台管理与内容访问分别授权。运维确需应急访问时走可审计授权，业务管理员和空间管理员的实际内容权限应在生产配置及验收中核对。现有直链的有效期及历史会话访问单列验证，按采用的机制明确撤权生效条件。
- **存量过渡。** 现有库保留当前可见模式用于兼容。启用受管库前预览成员、共享、智能体及程序入口的权限变化，经库负责人确认后再切换。首批新建试迁库可直接采用受管模式。
- **结果验收。** 产品维护人只可改产品库。售后 Viewer 可检索获权的售后 SOP，但无法查看指定客户库的标题、正文和附件。撤权后用原账号复测各启用入口，并对历史会话和旧链接的可控访问做验证。

### M3 资料审核与生命周期

- **改造入口。** 在文档列表和详情中显示业务状态、当前有效版、资料责任人、来源和复核日期，增加待审核队列。上传、手工编辑及飞书试迁资料可提交审核。已经发布的资料更新时保留当前有效版，候选版审核通过并完成解析和索引后再切换。
- **执行规则。** 维护人提交，审核人批准或退回。批准且索引就绪的版本才进入普通读者的正式列表、检索和问答。继续同步的来源更新进入候选版。下架时撤出正式访问范围，归档原件和必要的审批历史。Wiki、摘要、引用等衍生内容随生效或下架状态校验。
- **结果验收。** 用同一版本的产品手册演示上传、退回、发布，再提交新版本。审批和索引未完成时，读者仍使用当前有效版。新版本发布后，典型问答命中新版。下架后复测正式列表、问答、引用与原文入口。

### M4 飞书盘点和按清单迁移

- **改造入口。** 在知识库数据源管理基础上增设部门迁移批次入口。读取飞书资源树，导出或导入可编辑映射清单，支持逐项设置目标空间、知识库、目录、节点处理方式、批准人和权限结论，并展示预检结果。
- **执行规则。** 继续使用现有连接器获取正文、附件和原链接，使用现有上传、解析和索引能力。混合子树按逐项批准清单定向入库，每个节点和附件都在写入前校验，按批次限制暂存读者。使用飞书空间 ID、节点 ID、附件标识及来源版本或更新时间维持映射。不同节点若指向同一原文，结合原文标识、链接、内容指纹和人工确认去重，保留各源节点对应关系。同一源版本、同一目标位置和同一处理方式的条目重复执行时，复用已有记录。经批准的脱敏摘编按独立映射追踪。失败可按条目重试。
- **迁移预检。** 检查权限未确认、目标读者超范围、重复和同名冲突、父子层级拆分、失效链接、附件或文档格式异常，以及重复导入。首批采用执行前核定的清单、人工启动和关闭同步删除。目录纯净且权限一致的批次可用现有整树同步承接数据读取，再按同样的放行标准核对。
- **结果验收。** 用包含有正文父页、纯导航页、产品子页、受限客户子页、周报、快捷方式和失败附件的样例执行预检与试迁。验证同一子树可以拆到多个库、失败重试无重复，逐条查到原链接、目标位置及处理结果。

### M5 业务审计与迁移验收

- **改造入口。** 基于知识库活动和同步日志，增加业务审批与执行记录。覆盖建库和归档、负责人交接、成员授权与撤权、发布与下架、迁移确认和回退。库负责人在权限范围内查看记录，迁移经办人按批次导出映射和失败明细。
- **结果验收。** 能从一份已发布资料查回源节点、源版本、发布审批和所属批次。能从一条权限变更查到审批人、执行人、适用对象、有效期及撤权结果。能从整批对账清单确认每个源项的归宿，并核对重新执行后的状态。

## 三、部门目标知识库结构

下面用现有六类内容规划目标库。是否单独设工作空间由实际成员边界决定，是否独立建库由业务归属、可见对象和维护责任决定。以下名称、分工和可见对象是评审建议。

| 目标库或归档位置 | 放什么 | 建议目录 | 谁负责及谁可见 |
| --- | --- | --- | --- |
| 产品知识库 | 产品介绍、规格、功能说明、版本与发布说明、限制及产品操作说明 | 产品线 / 资料类型 | 产品负责人维护。部门已授权岗位可读。面向客户的版本需单独确认可发布范围 |
| 业务知识库 | 部门共同使用的业务流程、制度、岗位指引和模板 | 业务主题 / 流程或模板 | 部门业务负责人维护，部门相关人员可读 |
| 售前知识库 | 报价流程、通用方案、演示手册、投标模板、常见问题、可复用脱敏案例 | 场景或行业 / 方案、演示、投标、FAQ | 售前负责人维护，授权的售前及协作岗位可读。客户专属报价、投标和沟通记录进对应客户空间 |
| 售后知识库 | 交付 SOP、部署运维、故障排查、服务模板和已验证的通用经验 | 服务阶段 / 交付、运维、故障、FAQ | 售后负责人维护，授权的交付、支持和协作岗位可读。客户原始工单和环境资料进对应客户空间 |
| 客户或项目资料库 | 客户方案、专属报价、合同、纪要、项目交付、客户原始故障资料 | 客户或项目 / 售前、合同、交付、售后 | 客户或项目负责人维护。按同一获批名单建库或空间，有独立授权名单的客户须有独立隔离边界 |
| 部门周报归档 | 原始周报、项目进展以及阶段汇报 | 年 / 月或季度 / 周 | 部门运营或指定人员负责。原件建议留在飞书归档，确需迁入时进入限权归档库，按获批账户访问 |

**周报中可复用的内容。** 把经过验证的故障排查步骤、长期有效的流程改进、对外可用的客户案例提炼为独立知识，由对应产品、业务、售前或售后负责人审核后发布。保留原周报引用供获权人员追溯。例行进展、个人工作记录和时点性事项按周报归档，归档库如迁入识渊，默认排除在部门通用问答范围之外。

**多类内容同时出现时。** 每份正式资料一个权威归属。售前方案引用产品库规格，售后 SOP 引用产品操作说明。通用方法和客户专属信息混在同页时，先把两部分分开确认，通用部分可发布到专业库，客户原文进入限权库或留在飞书。处理后一份原文可对应多个脱敏摘编或正式资料，清单分别记录范围、版本和批准人。

## 四、飞书文档套文档的拆解方法

飞书父子关系只作为盘点线索。每个节点按正文、子节点、实际权限、关联附件和业务归属分别判断。

| 飞书节点情况 | 处理操作 | 目标效果 |
| --- | --- | --- |
| 父页只有菜单、链接和导航说明 | 生成目标库文件夹或索引页，保留有效跳转需要的链接映射 | 保留导航，减少无业务正文的条目参与问答 |
| 父页有正文且下面还有子页 | 父页正文作为一篇独立文档。子页逐条归类，同主题及同权限可继续归入同一文件夹 | 保留正文，允许子页按业务和权限移动到合适的库 |
| 父页和子页分别涉及不同业务或不同可见范围 | 逐条指定库和目录，重新核对附件、引用和可见人群。业务相关性用链接或标签表达 | 产品、售前、售后和客户资料可以各自维护和授权 |
| 同名、快捷方式、多个版本或内容重复 | 用节点 ID 和可识别的原文标识核对。业务负责人指定有效版，保留来源与旧版去向。只有疑似重复时先待复核 | 检索命中权威版本，历史引用仍可追踪 |
| 文档内嵌附件、表格、图片或链接 | 附件随归属文档核对实际权限和可用性。独立受限的附件单列。对表格、画板及视频抽查解析结果，记录降级或保留源链接 | 不遗漏关键材料，也能查清哪些内容须回飞书查看 |
| 权限未知、无负责人、临时过期或无可复用内容 | 登记原节点和原因，标明「待判定」「留飞书」「归档」或「确认废弃」 | 待判定项有责任人，排除结果可回溯 |

### 一棵混合子树的落库示例

以下节点均为示例。源树为「部门知识库 / 产品 A 资料」，根页有正文，子页来自多个岗位。

| 原节点 | 批准后的去向 | 处理方式 |
| --- | --- | --- |
| 产品 A 资料（根页，兼有导航与简介） | 产品知识库 / 产品 A / 产品简介 | 迁移正文，重写索引链接。客户条目从通用阅读入口移除 |
| 产品 A 功能及版本 | 产品知识库 / 产品 A / 版本说明 | 保留有效版并登记原链接 |
| 客户甲投标报价 | 客户甲受限库 / 售前 / 投标报价 | 仅获批项目成员可读，附件同步核对 |
| 通用演示手册 | 售前知识库 / 演示 / 产品 A | 复用官方产品说明链接 |
| 客户甲现场故障处理 | 客户甲受限库保留原件。审核后的通用排查步骤进入售后知识库 | 摘编记录来源，审核时检查客户信息已移除 |
| 第 42 周工作周报 | 飞书周报归档 | 仅把已验证的可复用经验摘编入相应正式库 |

## 五、上线、迁移与验收安排

| 阶段 | 工作与分工 | 交付和进入下一阶段的条件 |
| --- | --- | --- |
| 1. 盘点与确认 | 飞书管理员提供有访问授权的目录和权限信息。各业务负责人按实际节点核对分类、有效版本、人员和例外。技术人员核对生产版本、空间成员、共享与连接配置 | 目标库及负责人清单，飞书节点映射和待判定项，首批范围和验收样例 |
| 2. 模块开发与联调 | 先完成 M1、M2，再联调 M3。M4 的盘点和清单能力可并行开发，正式写入依赖目标库授权和发布状态。M5 随相应操作记录事件 | 完成前四个模块的场景联调，业务操作可在 M5 查到。已用测试账号核对授权和撤权 |
| 3. 小批试迁 | 选一个内容典型、权限可核对的产品或售前子树。受限权限和周报情况可用授权样本或测试数据验证。迁移经办人核对预检和结果，源与目标负责人共同验收 | 首批已批准条目均可对账。关键文档、附件、问答和权限用例达标 |
| 4. 分批切换 | 按业务主题及可见范围分批执行，建议先产品和通用业务、售前售后，再处理已获授权的客户资料和有保留需求的周报。每批记录权威来源、版本截止点、同步策略、下架计划和回退责任人 | 批次签字后开放，源节点与目标位置可查，后续由各库负责人维护 |

**验收标准建议。**

- **资料完整。** 已盘点节点均有明确处理结果。正式开放范围内的应迁资料全部成功入库并可检索，批准留在飞书、归档和废弃的节点有相应记录。失败按源节点核对和重试。
- **权限正确。** 约定的读、写、审批和撤权测试全部通过，已测场景的越权暴露为零。覆盖普通员工、不同部门或项目成员、库维护人、审核人、已撤权人员及启用的程序和问答入口。
- **知识可用。** 每类目标库用典型业务问题验证检索到有效版本和可核对的引用。关键资料及附件逐项验收，周报、待审文档和客户专属内容按既定范围出现在对应访问入口。
- **回退可操作。** 批次出现越权或关键资料异常时，暂停发布和同步，收回该批新增的成员、共享与智能体等入口，按批次清单下架受影响的条目或版本，恢复原访问来源。修复后用原验收样例复测。切换期保留源资料及版本记录。

部门试点建议以飞书为源、识渊承接通过审核的业务查询。每个批次在验收时确认继续以飞书编辑，或在版本核对后切换到识渊维护。继续同步时约定权限变更通知、目标撤权责任和删除处理方式。

## 六、清单字段与评审事项

| 清单 | 必要字段 |

| 知识库目录 | 目标空间和库 ID、业务分类、归属、主备负责人、可见模式、角色与共享对象、权威来源、状态、复核日期 |
